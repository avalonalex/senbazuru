# Glossary additions

The only definition of each term the PRDs introduce, or use more narrowly than
[`docs/glossary.md`](../docs/glossary.md). A PRD defines a term in one clause
and links here; a PRD needing an unlisted term adds its row here first. Where a
row and [decisions.md](decisions.md), the design record every PRD is written
against, disagree, the record wins and the row is corrected.

M0's first pull request moves these rows into `docs/glossary.md` (row 10 of
[the recorded-text table](decisions.md#3-recorded-text-this-design-changes),
written out in [01 §4.10](01-architecture.md#410-docsglossarymd)). *Origami*,
*The FOLD format* and *Geometry* are the glossary's own sections; *Words the PRDs
narrow* amends existing rows; the rest become new sections. Links are relative to
`PRDs/`, so the move rewrites them.

A row ends with where its term is decided: a decision by number, linked into
decisions.md (D3 is
[D3](decisions.md#d3-the-runner-owns-the-state-its-start-and-the-handoffs)); a
change to the earlier draft as C*n*, linked to
[Changes since draft v2](decisions.md#changes-since-draft-v2); a PRD by number
(`02` is [02-language-semantics.md](02-language-semantics.md)); a module (prefix
`Senbazuru.` dropped; `Sequence.`, `Material.` and `Numeric.` are planned); or a
research note and heading. "Owner decision N" is row N of
[decisions §9](decisions.md#9-owner-decisions). Code links are to lines read at
`568dcb6`. *Italics* name another row. The rest of the glossary, squash fold
included, is unchanged. *Sequence*, *step*, *frame*, *hold* and *rest angle* must
not gain new meanings.

## Words the PRDs narrow

| Term | Meaning |
| --- | --- |
| **Sequence** | As in the glossary: a diagram sequence stored as multi-frame FOLD. Never used alone for the program, which is a *sequence source* (text) or a `Sequence` (Haskell); its output is a *sequence file*. [#97](https://github.com/avalonalex/senbazuru/issues/97)'s "scheme" is retired ([D12](decisions.md#d12-the-text-syntax)). See [04](04-prd-sequence-source-and-cli.md). |
| **Step** | One `step { … }` block: the instruction for one picture in a book, holding one or more *moves*, so "fold and unfold both diagonals" is one step of two moves ([D1](decisions.md#d1-one-first-order-syntax-tree-built-by-name-only-builders)). It writes its authored `sample` poses, then its end state, each a *state*; its caption and arrows go on the *figure* of the state it starts from; a step whose moves are all `expect refused` writes nothing. Steps count from 1 in source order, including steps that write nothing, so a step number and a figure number can differ, and messages say "step N (name)" ([D24](decisions.md#d24-states-figures-and-their-numbers)). A metadata-only key frame is not a step ([`Steps.hs:85-89`](../src/Senbazuru/Render/Steps.hs#L85-L89)). See [02](02-language-semantics.md). |
| **Figure** | As in the glossary: one drawing on a page. On a page drawn from a run, figure *j* draws *state* *j* − 1, so figures follow states, not steps. The two-step quarter fold writes three states and draws three figures: the sheet with step `half`'s caption, the half-folded paper with step `quarter`'s, and the result with the `closing` caption. An authored `sample` pose is a figure with no caption and no arrows ([D24](decisions.md#d24-states-figures-and-their-numbers)). "Figure" is the page's word, "step" the source's. See [06 §2](06-prd-step-diagrams.md#2-from-a-run-to-notes). |
| **Flap** | Cut the paper along the fold line; the flap is every face still joined to a *seed*. This is `Origami.Flap`'s set, "the faces reached after removing the selected creases from the face graph" ([`Flap.hs:1-6`](../src/Senbazuru/Origami/Flap.hs#L1-L6)). |
| **Rest angle** | Only the spring sense: the angle a crease spring prefers during a *settle*, taken from a *rest pose*, never from an assignment. The glossary defines it twice, as a physical property at `:19` and a spring's preference at `:83`; M0 merges them. The physical sense is *springback*. See [07](07-prd-material-consumption.md). |
| **Collapse** | The move `collapse at P [keeping [Q1, Q2] flat]` covers only six precreased rays at one vertex closing at fixed relative rates, as in the square base and bird base; other cases are refused ([D9](decisions.md#d9-macro-moves-as-named-angle-relations)). See *macro-move*. |
| **Rabbit-ear fold** / **Petal fold** | As moves, each covers only geometry whose angle relation is derived and tested; for the petal, only the bird base's 22.5° case ([D9](decisions.md#d9-macro-moves-as-named-angle-relations)). |
| **Fold arrow** | On a page drawn from a sequence source, arrows come from *move records*: for each move that turns paper, one arrow per connected group of moving paper, with a head for valley, mountain or unfold ([D7](decisions.md#d7-a-typed-step-note-reaches-the-page)). Subtracting frames cannot find them: a fold-and-unfold leaves identical frames. See [06](06-prd-step-diagrams.md). |
| **Flat-folded** / flat state | A *flat state* has every face in one plane, so each angle is 0 or ±180°. The glossary's "exactly ±180°" misses precreases at 0. Constructions and settles need one. |

## Origami

| Term | Meaning |
| --- | --- |
| **Hinge** | The line a move turns paper about, as one rigid rotation, possibly through several segments and layers: "a fixed line about which the selected material vertices rotate" ([`HingeSweep.hs:2`](../src/Senbazuru/Origami/HingeSweep.hs#L2)). |
| **Precrease** / **fold and unfold** | Fold, then undo, leaving a crease that stays flat until a later move uses it ([precreases-and-target-states.md](../docs/notes/precreases-and-target-states.md)). `precrease` is the alias. It takes no angle and leaves two *move records*, the fold and the unfold ([D12](decisions.md#d12-the-text-syntax), [06 §2](06-prd-step-diagrams.md#2-from-a-run-to-notes)). Written frames show the crease as `F` at 0. |
| **Unfold** | `unfold NAME…` reverses the named steps' net angle changes, last move first, reusing each move's recorded hinge and seed. A move whose hinge creases are all at 0 already is skipped; a crease a later move changed is refused as `UnfoldChangedSince`. The creases remain ([D22](decisions.md#d22-figures-holding-several-moves)). |
| **Turn over** | Turn the whole model face-down; no crease changes. `left-right` is a half turn about the line parallel to y through the centre of the displayed model's bounding box, `top-bottom` about the line parallel to x, so the model stays where it is on the page. It is *presentation*; `white side up` starts with a `left-right` turn-over ([D5](decisions.md#d5-presentation-and-the-readers-side)). See [02 §5.2](02-language-semantics.md#52-presentation-moves-no-paper). |
| **Rotate** | `rotate k/8 turn clockwise \| anticlockwise`: spin the whole model about the line parallel to z through its bounding box's centre; eighths give a book's diamond view. *Presentation*. An odd k needs `cos` and `sin`, so written coordinates carry platform-dependent last bits (owner decision 10, [D5](decisions.md#d5-presentation-and-the-readers-side)). |
| **Inside reverse fold** / **outside reverse fold** | On a flap of two layers joined along one folded edge, two creases leave that edge so the flap's end turns inside out between the layers (inside), or wraps round them (outside). Several creases move together; `not modelled` for now ([D9](decisions.md#d9-macro-moves-as-named-angle-relations)). [E1](research/E1-prior-art-sequence-languages.md) "E. The human vocabulary". |
| **Sink** | Push a point inward, reversing the creases round it; an *open* sink lets layers spread, a *closed* one does not. Not modelled in v1. |
| **Swivel** | A flap turns about a fixed point while a crease forms along one edge. Not modelled in v1. |
| **Crimp** | Two reverse folds made together across a doubled strip. Not modelled in v1. |
| **Blintz** | All four corners of a square folded to its centre (`examples/blintz-base.fold`); the first study *recipe* to become a sequence ([D16](decisions.md#d16-testing-and-acceptance)). |
| **Helmet base** | A square halved along a diagonal, then both corners of the doubled triangle folded to its tip ([`HelmetSequence.hs:1-2`](../study/fold-material/HelmetSequence.hs#L1-L2)); the recipe `HelmetSequence`, the second to become a sequence ([D16](decisions.md#d16-testing-and-acceptance)). |
| **Bird route** | The study's one route from an open square to the bird base: six creases collapse together into a layered square base, then two petals lift and both press flat ([`CheckedBird.hs:1-4`](../study/fold-material/CheckedBird.hs#L1-L4)). It is the route the study's certificate covers, not a book's ([decisions §7](decisions.md#7-examples)). |
| **Crane wing** / **crane opening** | The *crane wing* is `CraneWing`: add a crease across one wing of `examples/crane.fold`, then turn that wing through 90° ([`CraneWing.hs:1-4`](../study/fold-material/CraneWing.hs#L1-L4)). The *crane opening* is a crane's first steps, from a square to a square base, an example sequence in [decisions §7](decisions.md#7-examples), **UNVERIFIED** there. |

## The FOLD format

| Term | Meaning |
| --- | --- |
| **Key frame** | A FOLD file's top-level object: file metadata and first frame at once. A *sequence file*'s holds metadata only ([D4](decisions.md#d4-written-frames-follow-the-state-rule)); a sequence's *sheet* is always one, never a `file_frames` entry. |
| **Sequence file** | What `run` writes: a metadata-only key frame, then `file_frames` holding the *states*: the starting state, then for each step that writes one, its authored `sample` poses and its end state ([D4](decisions.md#d4-written-frames-follow-the-state-rule), [D24](decisions.md#d24-states-figures-and-their-numbers), [C63](decisions.md#changes-since-draft-v2)). So the two-step quarter fold writes three states ([01 §5.9](01-architecture.md#59-the-written-frame-and-the-page-note)) and the five-step blintz six ([03](03-prd-embedded-dsl.md#acceptance-criteria) A-6). `Fold.Query` cannot tell it from a hand-written file. See [02 §11](02-language-semantics.md#11-written-frames). |
| **State** | One `file_frames` entry of a *sequence file*, numbered from 0 by its index; state 0 is the start, and "state k" in prose always means `file_frames[k]`. `--frame N` on any verb selects state N − 1, because frame 0 is the key frame ([D13](decisions.md#d13-the-run-verb-and-io), [D24](decisions.md#d24-states-figures-and-their-numbers)). A hand-written file may keep its first state in the key frame instead: `quarter-fold-steps.fold` has 9 key-frame vertices and 2 `file_frames` (`jq`, [06](06-prd-step-diagrams.md#what-the-page-draws-today-with-real-numbers)). |
| **Written frame** | A frame from `Sequence.Write`: explicit `edges_foldAngle`, *state rule* assignments, no `U`, faces in the sheet's winding so an upside-down face shows its back ([D4](decisions.md#d4-written-frames-follow-the-state-rule)). |
| **State rule** / **at rest** | `B`, `C`, `J` kept; else `M` below −τ, `V` above τ, and `F` between, written with angle exactly 0. τ is `Fold.Query.atRest`, 1e-10 degrees, equal to the literals at [`Surface.hs:278`](../src/Senbazuru/Origami/Surface.hs#L278) and [`StudyCase.hs:208`](../study/fold-material/StudyCase.hs#L208). So a flat precrease is written `F` though made as a valley; that survives as the *intent assignment*. Related to [#111](https://github.com/avalonalex/senbazuru/issues/111). [D4](decisions.md#d4-written-frames-follow-the-state-rule). See [02 §11](02-language-semantics.md#11-written-frames). |
| **Intent assignment** | The `M` or `V` a crease was made as, kept on the *working pattern* while it lies at 0, so a later collapse or settle knows its direction and `Flap`, which turns only `M`, `V` or `U` ([`Flap.hs:187`](../src/Senbazuru/Origami/Flap.hs#L187)), can hinge on it. At the start `M` and `V` are kept, an `F` crease beyond ±τ becomes `M` below −τ and `V` above τ, and `U` stays `U` whatever its angle: `F` at an angle contradicts itself, `U` at an angle does not, and the runner must not invent intent ([D3](decisions.md#d3-the-runner-owns-the-state-its-start-and-the-handoffs), [C17](decisions.md#changes-since-draft-v2)). Move records carry it; written frames do not. |

## Geometry

| Term | Meaning |
| --- | --- |
| **Proper rotation** | A rigid motion with determinant +1, so no mirror; a mirrored model folds fine and is wrong. Checked for presentation, since `Rigid` "will hold any 3×3 matrix … and nothing here checks" ([`Rigid.hs:24-26`](../src/Senbazuru/Geometry/Rigid.hs#L24-L26)). |
| **Ordered cover** | For each stretch of a line across a folded model, the faces over it, nearest first from the *reader's side*; refused where overlapping faces have no order. Built on `Visible.nearness` ([`Visible.hs:240`](../src/Senbazuru/Origami/Visible.hs#L240)). See [05](05-prd-library-additions.md). |
| **Sweep interval** | A stretch of a hinge turn's angle `HingeSweep` examines: clear if every triangle pair is provably apart, else halved. The count is capped (4096, [`HingeSweep.hs:95`](../src/Senbazuru/Origami/HingeSweep.hs#L95)); the cap gives *unresolved*, never *clear* ([`:455`](../src/Senbazuru/Origami/HingeSweep.hs#L455)). Budgets count these, not seconds. |
| **ulp** | "Unit in the last place", the gap to the next `Double`. The manifest's rabbit-ear literal is one ulp from its formula and fails `==`, so formula angles use a named tolerance. [gap-exact-landmarks-and-macro-binding](research/gap-exact-landmarks-and-macro-binding.md) "Summary" (Python). |

## The sequence language

| Term | Meaning |
| --- | --- |
| **Sequence source** | The text an author writes, first line `foldseq 1`, extension `.foldseq` (a placeholder, owner decision 1). A program, not an input format: it becomes FOLD only when run ([D12](decisions.md#d12-the-text-syntax)). See [04](04-prd-sequence-source-and-cli.md). |
| **Move** | One instruction in a step (fold, unfold, turn over, *macro-move*, `pose` …), checked alone. Each leaves one *move record* except three: `let`, which *elaboration* expands away; `not modelled`, which stops the run; and `expect refused`, which changes nothing ([02 §6.1](02-language-semantics.md#61-every-move)). [#60](https://github.com/avalonalex/senbazuru/issues/60)'s `Move` now means this. |
| **Sheet** | The starting paper: `sheet square`, the unit square, or `sheet "path"`, a key frame read by `Fold.Load`. Plain `sheet` sets every angle to 0; `start folded { … }` keeps the file's angles and names the *stacking* ([D3](decisions.md#d3-the-runner-owns-the-state-its-start-and-the-handoffs)). See [02](02-language-semantics.md). |
| **Let** | `let NAME = …` names a point or line, re-evaluated at each use; it pins nothing (compare *mark*). |
| **Together** | `together { … }` advances several macro-moves in lockstep as one move with one *move record*, each member advancing by the same fraction of its own range; members may not share a crease ([D9](decisions.md#d9-macro-moves-as-named-angle-relations)). |
| **Sample** | `sample 30° 60° …` picks poses on a macro's route, in the macro's own parameter and strictly inside the stretch it runs. Each is written as a *state* and drawn as a figure with no caption and no arrows. Checking does not depend on them: the runner also checks `RunSettings.macroChecks` evenly spaced poses, so a macro with no `sample` is still checked ([D9](decisions.md#d9-macro-moves-as-named-angle-relations), [D24](decisions.md#d24-states-figures-and-their-numbers)). **A second sense, in a settle only:** a point of the refined mesh that a *hold* or *grip* region tests, by its material coordinates or its position in `recordBefore`. Those points exist only once `settle` refines, so a region stores its test as data ([D14](decisions.md#d14-material-consumption), [07](07-prd-material-consumption.md#naming-holds-and-grips)). The first sense is a pose, the second a point. |
| **Repeat** | `repeat NAME[..NAME]` reruns named steps, optionally `mirrored across [P, Q]` or `turned k/4 about P`. The runner checks that the new creases are the symmetric image of the originals **and** that each hinge's image turns by the same net angle, because a repeat along existing creases adds no crease and would otherwise compare nothing ([D21](decisions.md#d21-repeat-checkpoint-not-modelled-expect-refused)). One figure with a *repeat range*. |
| **Checkpoint** | `checkpoint "path" { … }` replaces the paper with a loaded key frame, claiming no route (`StateOnly`), for stretches no move expresses yet. Its angles are read as `start folded` reads them, and its stacking is chosen as `start folded` chooses one. It may add or remove creases, so it starts a figure with no arrow ([D21](decisions.md#d21-repeat-checkpoint-not-modelled-expect-refused)). |
| **Not modelled** | `not modelled "…"` stands in for a move the library lacks. `run --check` accepts it; the runner stops there, keeping every state before it, and `run` writes those and exits nonzero naming the step ([D21](decisions.md#d21-repeat-checkpoint-not-modelled-expect-refused)). |
| **Expect refused** | `expect refused KIND { move }`, a move inside a step, requires the inner move to be refused with that kind. It changes nothing and leaves no *move record* and no *state*; its outcome is kept in the *run* and printed by `run --report`: a record of which way a fold is physically possible ([D21](decisions.md#d21-repeat-checkpoint-not-modelled-expect-refused)). |

## References

| Term | Meaning |
| --- | --- |
| **Reference** | Anything naming paper or a line: `corner north-west`, `(1/4, 1/5)`, `edge north to edge south`, `hinge of wing`. Never a raw id, since creasing renumbers ids. Resolved against the current state and recorded ([D2](decisions.md#d2-references-named-on-the-sheet-and-resolved-by-slot)). See [02](02-language-semantics.md). |
| **Material point** | A point named by material coordinates: one piece of paper for the whole sequence, where a folded position can lie on several layers. |
| **Sheet compass** | Material names by compass on the unfolded sheet: `corner south-west`, `edge north`, `centre`; north is +v. They never change as paper moves. `corner X` and `edge S` are refused unless the sheet's boundary has a vertex or edges there. Left, right, top, bottom, front and behind are reserved for what the reader sees ([D2](decisions.md#d2-references-named-on-the-sheet-and-resolved-by-slot)). |
| **Sheet length** | A source's coordinate unit: the sheet box's larger side is 1 and its south-west corner (0, 0), so `(1/2, 1/2)` is the centre of a 400-unit `.cp` square and a unit `.fold` square alike. Outputs stay in model units, which a source writes only inside `model [...]`. |
| **Position/region/vertex slots** | A point resolves by its slot, not its spelling. A *position* (construction input) may be anywhere, but every face containing it must agree. A *region* (`anchor`, `layers A above B`) must be strictly inside one face; a seed may also be a vertex. A *vertex* (`collapse at`) must be within tolerance of exactly one. |
| **Near miss** | A typed `(u, v)` or `model [...]` literal near a vertex but not on it (within `RunSettings.nearMissBand`, default 1e-3 sheet lengths by owner decision 2), refused naming the vertex, since it meant the vertex. `corner`, `centre`, `midpoint of` are exact. |
| **Construction** | A point or line computed from references: a *Huzita-Hatori operation*, `meet`, `midpoint of`. Flat states only. Solutions off the paper are reported, never dropped or chosen. |
| **Huzita-Hatori operation (O1-O7)** | The glossary's seven axioms, numbered as in E2: O1 `[P, Q]`; O2 `P to Q`; O3 `L1 to L2`; O4 `perpendicular to L through P`; O5 `P to L through Q`; O6 `P to L1 and Q to L2`; O7 `P to L1 perpendicular to L2`. Folding along an existing crease (`crease [P, Q]`) is Lucero's eighth. [E2](research/E2-references-and-persistent-naming.md) "B. Huzita–Justin–Hatori: the vocabulary of fold lines". |
| **Disambiguator** | The reference picking one of several valid answers: `nearest P` (construction), `keeping [Q1, Q2] flat` (collapse), `in face containing S` (stacked layers). Named by material point, never id; zero or several left is refused, listing candidates. |
| **Seed** | A material point naming what moves: `moving P`, or a fold's first argument. The *moving side* is paper joined to it after cutting along the line; the rest is *stationary*. The anchor never decides. |
| **Flap containing** | `flap containing P`: the flap holding seed P, the default for an *alignment fold*. |
| **Top flap** | The fewest layers, counted from the reader's side, that turn without dragging joined paper. `top N layers` takes N; `all layers` everything. [gap-layer-selective-folds](research/gap-layer-selective-folds.md) "(a) A rule from line + selector to a face set". |
| **Layer selection** | The faces a fold moves when it folds only some layers, picked by `flap containing P`, `moving P`, `top layer`, `top N layers`, `top flap` or `all layers`, then pinned in the record as material seeds. The rule cuts the crossed faces along the line, and refuses a *coupled* selection or one a stationary face covers on the side it turns towards (`FlapCovered`) ([D8](decisions.md#d8-folding-some-layers)). See [02 §6.3](02-language-semantics.md#63-which-layers). |
| **Landmark** | A named point or crease: a `mark`, or a step name in `hinge of NAME` / `crease of NAME`. Names are unique. |
| **Mark** | `mark A = P [in face containing S]` pins the material point at folded position P and labels it while visible; S picks one layer where P lies on several. |
| **Alignment fold** | A fold given by what it brings together (`P to Q`, `L1 to L2`, `P to L`). Unrelated to *anchor placement*. |

## Running a sequence

| Term | Meaning |
| --- | --- |
| **Runner** | `Sequence.Run.runSequence`, the pure function performing a checked, elaborated `Sequence` move by move and returning a *run*. It threads a *fold state* but never returns one. No I/O ([D23](decisions.md#d23-the-sequence-modules-and-where-run-lives)). See [01](01-architecture.md). |
| **Run** | `Run`, defined in `Sequence.Record`: what a reader of a run needs, namely the start state, every *move record*, each step's outcome (its records, authored samples and expected refusals), the closing caption, and where a `not modelled` move stopped it, if one did. It holds no *fold state*, so no renderer can come to depend on the working pattern. `writtenStates` turns it into the *states* the file writer and the page both read ([D23](decisions.md#d23-the-sequence-modules-and-where-run-lives)). |
| **Fold state** | `FoldState`, abstract, in `Sequence.Run`: *working pattern* with accepted orders, directional layer requirements, anchor, anchor placement, presentation, landmarks, macro bindings, and which step made each crease (so `crease of NAME` resolves) ([D3](decisions.md#d3-the-runner-owns-the-state-its-start-and-the-handoffs)). |
| **Working pattern** | The pattern the runner folds: cut at crossings, material coordinates, explicit angles, *intent assignments*. Folded coordinates never come back as material. See [02](02-language-semantics.md). |
| **Anchor** | The material point whose face stays still, which is why a fold moves the flap, not the model. Default: the *vertex mean* (the average of the corner coordinates) of the initial pattern's largest face, ties to the lowest then leftmost vertex mean, as `StudyCase` ranks faces by area, then negated mean y, then negated mean x ([`StudyCase.hs:242-248`](../study/fold-material/StudyCase.hs#L242-L248)). A vertex mean, not an area centroid: the two agree on triangles and squares but not on a general quadrilateral. `anchor P` overrides ([D3](decisions.md#d3-the-runner-owns-the-state-its-start-and-the-handoffs), [C20](decisions.md#changes-since-draft-v2)). |
| **Re-anchor** | When a move would carry the anchor's face, the stationary face beside the hinge with the largest material area becomes the anchor face, ties to the lowest then leftmost vertex mean, never to face id; its vertex mean becomes the anchor, recorded. Refused as `ReanchorNotFlat` if that face is not flat in the page. Re-anchoring is owner decision 3's default; refusing is its alternative ([D3](decisions.md#d3-the-runner-owns-the-state-its-start-and-the-handoffs)). |
| **Anchor placement** | The rigid motion keeping the picture still across a re-anchor: folding puts the new anchor face at the origin, the anchor placement puts it back. A *proper rotation*, identity at start ([D3](decisions.md#d3-the-runner-owns-the-state-its-start-and-the-handoffs)). Called "anchor placement", never "alignment", so it cannot be confused with an *alignment fold* ([C60](decisions.md#changes-since-draft-v2)). |
| **Presentation** | The rigid motion turning the whole model for the reader (`turn over`, `rotate`); moves no paper. Written frames are presented; a *move record*'s surfaces are not, and it keeps presentation and anchor placement, before and after, as separate fields ([D5](decisions.md#d5-presentation-and-the-readers-side), [D14](decisions.md#d14-material-consumption)). See [02](02-language-semantics.md). |
| **Reader's side** | Model +z after presentation. Starts coloured side up (or `white side up`); `turn over` flips it, `rotate` and re-anchoring do not. Valley, mountain, `top N layers` and `layers A above B` are read from it, never from a camera ([D5](decisions.md#d5-presentation-and-the-readers-side)). |
| **Sense** / **raw sense** | A fold's *sense* is valley or mountain as the author wrote it, seen from the *reader's side*: `in front` is valley, `behind` is mountain, spelled `ValleyFold` and `MountainFold` in the tree so they do not clash with `Fold.Types`' constructors. The *raw sense* is that sense negated exactly when presentation after anchor placement turns +z to −z; it names the assignment of new creases, and is what creasing through layers is handed ([D5](decisions.md#d5-presentation-and-the-readers-side)). See [02 §5.3](02-language-semantics.md#53-one-conversion-for-the-whole-model). |
| **Handoff** | Passing a move's result on: carry angles and orders to the working pattern, drop stale faces and `frameExtras`, refold from angles, never patch a `Folded`. [A2](research/A2-study-recipes-as-proto-dsl.md) "(b) The shared handoff policy: invariants an interpreter must enforce". |
| **Refold** | One `foldFrameWith` call recomputing every position from the angles. The runner refolds after every *handoff*, about seven times per checked step by a count from the code, not a timing ([D3](decisions.md#d3-the-runner-owns-the-state-its-start-and-the-handoffs); [gap-sequence-cost-and-test-budget](research/gap-sequence-cost-and-test-budget.md) "From reading the code (counts, not timings)"). Test budgets count refolds ([D16](decisions.md#d16-testing-and-acceptance)). |
| **Join check** | Per-step proof the paper neither tore nor drifted: positions within 1e-12 × the model's size (`modelSpan`) ([`BlintzSequence.hs:69`](../study/fold-material/BlintzSequence.hs#L69)); angles, edges, orders, material coordinates and face rings (as vertex sets) exactly equal, as at [`CheckedBird.hs:145-146`](../study/fold-material/CheckedBird.hs#L145-L146). |
| **Travel** | The signed change a hinge turn makes to a FOLD angle, in degrees ([`Flap.hs:10-11`](../src/Senbazuru/Origami/Flap.hs#L10-L11)), at most 360 ([`:165`](../src/Senbazuru/Origami/Flap.hs#L165)). It is the change in the *first* hinge segment's angle, and a segment whose stationary face lies upside down changes with the opposite sign ([`:14-16`](../src/Senbazuru/Origami/Flap.hs#L14-L16)). **The line that looks like a typo:** quarter-fold step 2, one valley fold, takes edge 9 to +180 and edge 11 to −180, because step 1 turned edge 11's stationary face over (`jq` on `quarter-fold-steps.fold`'s `file_frames[1]`). So the sign depends on the *raw sense* and on which way up the first segment's stationary face lies, and the library sets it from a side ([D5](decisions.md#d5-presentation-and-the-readers-side)). |
| **Coupled** | Of a selection: moving paper still joined to paper that must stay, refused naming the joining face. Of a move: several creases turning at tied rates, which a *macro-move* does. |
| **Stacking** | One complete *layer order* where a model has several. Accepted orders carry forward, never re-solved or chosen silently ([D11](decisions.md#d11-stacking-choices-are-relations)). |
| **Stacking relation** | `layers A above B`: paper at material point A over paper at B, from the reader's side. Relations must leave exactly one stacking; `stacking first` takes the solver's first as a stated default. Records keep the choice ([D11](decisions.md#d11-stacking-choices-are-relations)). |
| **Open pair** | Two overlapping faces whose order differs among remaining stackings; refusals list them. |
| **Directional layer requirement** | A direction plus lower/upper face pairs a material solve respects, which "may constrain separated panels too" ([`Surface.hs:119-121`](../src/Senbazuru/Origami/Surface.hs#L119-L121)). |
| **Layer budget** | `Budget`, "how many guesses the solver may make in one component before giving up", counted so files behave alike everywhere ([`Stacking.hs:151-165`](../src/Senbazuru/Origami/Stacking.hs#L151-L165)). `--layer-budget` reaches `runSequence` and `stepPageWith` too ([D7](decisions.md#d7-a-typed-step-note-reaches-the-page), [D11](decisions.md#d11-stacking-choices-are-relations)). |
| **Move record** | `MoveRecord`: one per **move**, so a *step* holding several moves has several, and `let`, `not modelled` and `expect refused` leave none. Unpresented surfaces before and after in one numbering; presentation and anchor placement, before and after; evidence; hinge, moving and stationary paper by material point; new creases; angles; stacking choice; resolved references; macro bindings. Pages, animation and the material consumer read it. "Step record" is retired ([D14](decisions.md#d14-material-consumption), [C60](decisions.md#changes-since-draft-v2)). See [01 §2.2](01-architecture.md#22-contract-1-moverecord). |
| **Material consumer** | The code that bends paper for a sequence: it takes *move records* and a step's `settle` block, never files, resolves the block's holds and grips against one record, and hands the solver a resolved `SettleInput` (**SKETCH**). It is `Sequence.Material`, a module of the *material study* importing `Sequence.Record` until *graduation* at M8 ([decisions §1](decisions.md#1-the-two-halves-today-and-what-connecting-them-means) "Contract 2", [D14](decisions.md#d14-material-consumption), [D15](decisions.md#d15-graduation-from-study-to-library)). See [01 §2.3](01-architecture.md#23-contract-2-the-settle-input), [07](07-prd-material-consumption.md). |
| **Verb** | A CLI subcommand. Today there are six, `render`, `info`, `check`, `export`, `crease` and `fold` ([`Cli.hs:220-242`](../app/Senbazuru/Cli.hs#L220-L242)), and every one reads its input through `withFoldFile` ([`:691-698`](../app/Senbazuru/Cli.hs#L691-L698)); `run` is the planned seventh and the only one that does not ([D13](decisions.md#d13-the-run-verb-and-io)). See [04](04-prd-sequence-source-and-cli.md#the-run-verb). |

## Macro-moves

| Term | Meaning |
| --- | --- |
| **Macro-move** | A move turning several creases at geometry-fixed rates: `collapse at`, `rabbit-ear at`, `petal` in v1. A library angle relation with a *signature*, not a composition of folds ([D9](decisions.md#d9-macro-moves-as-named-angle-relations)). See [02](02-language-semantics.md). |
| **Signature** | What a macro requires of a *moving star*. Collapse: six moving rays, sectors 45°, 45°, 90°, 45°, 45°, 90° up to rotation and reflection, each straight to the edge. No match refuses; several need a *disambiguator*. [gap-exact-landmarks-and-macro-binding](research/gap-exact-landmarks-and-macro-binding.md) "B. Signatures, checked by hand". |
| **Moving star** | The glossary's *star*, keeping what would move: at a vertex, the creases the macro turns (for a collapse, those at 0 with intent `M` or `V`), with angles and intent signs, collinear continuations merged. |
| **Role** | A crease's part in one match, fixing its formula: in a collapse, the *pair* of opposite rays between 45° sectors, and the *four*. Unique within a match; matches are not (a bird base has two petals). |
| **Driving parameter** | The one number a macro advances by, `until 175°`, an unsigned `Rational`; every role's angle is a formula of it. Stored exactly. |
| **Continue** | `continue NAME until A°` resumes a macro from its *macro binding* (roles, branch, disambiguator, parameter reached), after checking the paper still matches. |
| **Pose** | A full set of crease angles and the positions they fold to. `pose { crease [P, Q] at -90°; … }` sets named creases' angles claiming no route (`StateOnly`), and is allowed with paper in the air. **The sign looks like a typo:** a pose angle is a FOLD angle converted once for the whole model, negated only when the display turns +z to −z, with no per-layer flip, so +90° is a valley as seen only on paper lying the same way up as the anchor's face ([D9](decisions.md#d9-macro-moves-as-named-angle-relations)). A `RoutePose` is a pose on a checked route; `rigid-pose p` is a *grip* target. |

## Material

| Term | Meaning |
| --- | --- |
| **Settle** | A static material solve bending a step's rigid result, starting from its flat before-state, requested by a `settle { … }` block and bound to the step's last moving *move record*. A checked rigid state is already an equilibrium, so a settle whose rest is the before-state with no exceptions and whose every target lies on the before-state is refused as `NoDifference`: it must move a *hold* or *grip* target, or rest at another *rest pose* ([D14](decisions.md#d14-material-consumption), [C39](decisions.md#changes-since-draft-v2)). [B](research/B-material-study-mechanics.md) "Summary". See [07](07-prd-material-consumption.md). |
| **Settled illustration** | A settle's bent surface in its own files (`crane.settled-wing.glb`); never replaces a rigid frame, feeds later steps, or rescales a page. |
| **Hold** | Mesh vertices fixed exactly during one solve, unlike a rest angle ([wing-root-holds.md](../docs/notes/wing-root-holds.md)). Named against the *move record*, never by id, as a `SettleRegion`: `side stationary\|moving`, `across-hinge S`, `closed R`, `band`, `material-band`, `crease-line [P, Q]`, `hinge of NAME`, `layer upper\|lower of R`, `union`, `minus` ([D14](decisions.md#d14-material-consumption)). [gap-study-consumption-contract](research/gap-study-consumption-contract.md) "(b) Hold, grip and contact names that survive refinement and re-cutting". |
| **Pin** | One mesh vertex together with the exact position a *hold* or *grip* fixes it at. `CraneSpread` keys its pins by mesh vertex id, ids that *refinement* makes and a sequence may not name ([07](07-prd-material-consumption.md#what-that-interface-cannot-survive)). |
| **Grip** | A hold whose target moves: `rigid-pose p` (part-way along the rigid route) or a registered generator such as `arc-grip ROOT° EXTRA°` (`CraneSpread` accepts 0–20° extra, [`CraneSpread.hs:82-83`](../study/fold-material/CraneSpread.hs#L82-L83)). |
| **Band** | `band S d0..d1`: vertices on side S whose start-pose distance from the hinge line is d0–d1 sheet lengths; `material-band` uses material coordinates. **UNVERIFIED**: `band moving 0..1/32` equals the crane recipe's root strip. |
| **Rest pose** | The pose whose angles every active crease spring prefers in a settle (`RestAtPose`), with optional exceptions. |
| **Refinement** | Splitting panels into triangles, level 0–5 ([`Surface.hs:337`](../src/Senbazuru/Origami/Surface.hs#L337)), sharing edge midpoints and creating no crease ([`:314-316`](../src/Senbazuru/Origami/Surface.hs#L314-L316)). A settle names what it refines, `refine REGION INTEGER`, such as `refine side moving 3` ([D14](decisions.md#d14-material-consumption)). |
| **Verdict** | `Accepted` or `Diagnostic [Reason]`; converged but breaking a length, contact or hold check is diagnostic. It refuses only that step's settled files; rigid geometry is never substituted. |
| **Graduation** | Moving study code into the library in seven gated stages, [#208](https://github.com/avalonalex/senbazuru/issues/208)'s line search landing first; until then the consumer lives in `study/` ([D15](decisions.md#d15-graduation-from-study-to-library)). See [07](07-prd-material-consumption.md). |
| **Held boundary** / **Gauss–Newton** / **line search** | The study solver holds part of the sheet and lets the rest settle; each iteration linearises length errors, solves a sparse system for a correction, and picks a step length. [B](research/B-material-study-mechanics.md) "Summary". |
| **Penalty contact** / **barrier contact** | A penalty charges for overlap, so leaves tiny overlaps (a touching start ends at −5.9e-11); a barrier charges as layers approach. Penalty rows graduate first. [B](research/B-material-study-mechanics.md) finding 11 (repository notes). |
| **Springback** | A pressed crease reopening partway when released. Research only. |
| **Triangle budget** | The largest mesh `run --settle` accepts: 1,192 triangles until timed runs after #208 justify more; default CI at most 392. Both pass in the crane-wing study. [B](research/B-material-study-mechanics.md) "Capability table (question a)". |
| **Material block** | `material { … }`: sheet size, thickness, an illustrative stiffness preset and rest policy, with unit suffixes (`15cm`). Thickness is stored, unused in v1. |
| **Crane spreading** | `CraneSpread`: bending the lowered *crane wing* with the rest of the sheet kept, the body fixed, a short root strip held at 30° and a tip grip turned a further 20° ([`CraneSpread.hs:1-8`](../study/fold-material/CraneSpread.hs#L1-L8)); the settle the crane-wing example sequence re-expresses at M6 ([D14](decisions.md#d14-material-consumption)). |

Its ids belong to one cut and traced pattern, so adding any crease breaks it ([decisions §1](decisions.md#1-the-two-halves-today-and-what-connecting-them-means)). See [09 §9](09-testing-and-acceptance.md#9-migrating-the-study-recipes). |
| **Manifest** | `study/fold-material/cases.json`, read by `StudyCase`: each case names a FOLD file and gives a complete angle list for each named state, in that file's edge order ([`StudyCase.hs:5-6`](../study/fold-material/StudyCase.hs#L5-L6)). |
| **Guard** | A test line guarding a *recipe*: an assertion or golden that fails if the recipe's output changes, such as `checked-blintz.svg` for `BlintzSequence`. [gap-study-consumption-contract](research/gap-study-consumption-contract.md) "(d) Migration table" lists each recipe's guards, the tests its migration must not break. |
| **Equivalence PR** / **deletion PR** | The two pull requests retiring a *recipe*. The equivalence PR adds the sequence beside the recipe, both built once in `beforeAll`, and requires the same records (exact end angles, order and frame counts; material error within 1e-12) with goldens byte-identical. The deletion PR then removes the recipe from the cabal file and points gallery and spec at the sequence ([D16](decisions.md#d16-testing-and-acceptance)). See [09 §9](09-testing-and-acceptance.md#9-migrating-the-study-recipes). |
| **Milestone** | A group of pull requests that leaves `main` working, not a release: M0–M8, with M7 split into M7a and M7b, and R for research ([decisions §8](decisions.md#8-milestones)). See [10 §1](10-roadmap-risks-questions.md#1-milestones). |
| **Default CI** / **slow job** | *Default CI* is today's three checks every PR must pass, the jobs `test`, `format` and `lint` ([`ci.yml:11`](../.github/workflows/ci.yml#L11), [`:36`](../.github/workflows/ci.yml#L36), [`:71`](../.github/workflows/ci.yml#L71)). The *slow job* is a proposed fourth job running crane-sized specs under `describe "slow"` with `--match /slow/`, which the default job skips; whether it is required is owner decision 12 ([D16](decisions.md#d16-testing-and-acceptance)). See [09 §6.3](09-testing-and-acceptance.md#63-beforeall-not-runio-and-a-slow-job). |
| **Owner decision** | A choice left to the repository owner, numbered 1–12 in [decisions §9](decisions.md#9-owner-decisions), each with a recommended default the PRDs follow until it is decided; [10 §6](10-roadmap-risks-questions.md#6-owner-decisions) uses the same numbers. |
| **SKETCH** / **UNVERIFIED** | Markers in the PRDs: **SKETCH** is a planned name, type or message no code has yet; **UNVERIFIED** is a claim no command has checked, stated with what would check it. |
